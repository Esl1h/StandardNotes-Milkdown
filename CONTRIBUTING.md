# Contributing to StandardNotes Milkdown

Thanks for helping out. This is a small, focused editor: a WYSIWYG Markdown
editor for Standard Notes, powered by Milkdown Crepe, that keeps the note
as plain Markdown.

By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development setup

```
git clone https://github.com/Esl1h/StandardNotes-Milkdown.git
cd StandardNotes-Milkdown
npm ci
npm test
npx playwright install chromium
npm run e2e
npm start
```

`npm ci` installs everything from `package-lock.json` (the dependencies are listed in
`package.json`), `npm test` runs the unit tests, `npm run e2e` the browser tests and `npm start`
the dev server at `http://localhost:3002`. The Node version is in `.nvmrc`.

To test inside your Standard Notes app:

```
npm run build
npm run server-cors
```

Then install `http://localhost:3000/ext.dev.json` via Preferences > Plugins
(dev extension, separate identifier).

## Before opening a PR

1. `npm run typecheck`
2. `npm run lint`
3. `npm run format:check`
4. `npm test`
5. `npm run build`
6. `npm run e2e` (run `npx playwright install chromium` once first)

All six must pass. CI runs the same steps (and a few more checks) on every pull request and on
every push to `main`, on Node 22 and 24, and reports the result on the pull request. A change
that does not pass is not merged.

## Coding standards

- TypeScript in `strict` mode (`tsconfig.json`, checked by `npm run typecheck`)
- ESLint with the configuration in `eslint.config.mjs` (ESLint recommended, typescript-eslint
  recommended and the React hooks rules), run by `npm run lint`
- Prettier with `.prettierrc` (single quotes, 100 columns), run by `npm run format:check`; fix with
  `npm run pretty`
- Comment the why, not the what
- A style exception needs a comment at the place it is made, and should be rare

CI runs lint and the format check, so a pull request that breaks the style fails.

## Tests

Test policy: tests for new functionality MUST be added to the automated suite in the same pull
request, and a pull request that adds functionality without them is not merged. A bug fix MUST
come with a regression test that fails without the fix. Unit tests live next to the code in
`src/` (Vitest); behavior that needs a browser goes in `e2e/` (Playwright). `npm run test:coverage` reports statement coverage; do not lower it.

## Commit messages

Follow [Conventional Commits](https://www.conventionalcommits.org/): one
logical change per commit, subject in the imperative mood, body explaining
the why when the what is not enough.

## Releases

Maintainers: the steps are under [Releases](README.md#releases) in the README. `CHANGELOG.md` is generated by git-cliff from the commit subjects, so a `feat` or `fix` subject is what users will read there.

## Scope guidance

How decisions are made and who does what is in [GOVERNANCE.md](GOVERNANCE.md).

The note stays plain Markdown, round trippable with any other editor.
Features that store data outside the note, change the Markdown dialect
incompatibly, or add network access (no AI providers) do not fit the
project.
